## Why this matters

`pnpm audit` reports **8 advisories (5 high, 2 moderate, 1 low)**. Three have
published fixes and can be closed with the override mechanism this repo already
uses for exactly this purpose — `pnpm-workspace.yaml` carries 17 such entries.

The two `toml` advisories are the highest-severity fixable items, reached through
the **build/deploy** path:

```
@astrojs/netlify > @netlify/vite-plugin > @netlify/dev > @netlify/functions-dev
  > @netlify/zip-it-and-ship-it > toml
```

`toml` parses configuration during Netlify function bundling, so prototype
pollution there is a build-integrity concern rather than a runtime one — but it
is cheap to close and there is no reason to carry it.

**Two of the five high advisories have no upstream fix** and are explicitly out
of scope: `image-size` (two DoS advisories, via `@netlify/dev-utils`) and
`extract-zip` (symlink traversal, via `@netlify/functions-dev`). Both report
`patched: <0.0.0`. Both are dev/build-time only. Record and monitor; there is no
action available today.

```yaml
  undici: ">=7.29.0"

  "astro>svgo": ">=4.0.2"
  "ipx>svgo": ">=4.0.2"

```

Note the two styles: a bare package name overrides it everywhere; the
`"parent>child"` form scopes the override to one dependency path. Prefer the
bare form here unless a scoped override proves necessary.

## Scope

**In scope**:

- `pnpm-lock.yaml` (regenerated by `pnpm install` — commit the result)

**Out of scope** (do NOT touch):
- `image-size` and `extract-zip`. No upstream fix exists; forcing a version would
  break Netlify's dev tooling for no security gain.
- The `@netlify/blobs` 10→11 major upgrade. That is plan 186, has a much larger
  blast radius, and may close the `@opentelemetry/core` advisory as a side effect
  — but this plan closes it now, cheaply, without that risk.
- Any direct dependency version in `package.json`. These are all transitive.
- The `typescript: "6.0.3"` exact pin — it is deliberate and gated by
  `@astrojs/check` compatibility.
- Routine minor-version drift (`tailwindcss`, `eslint`, `@playwright/test`, etc.).
  No advisory, no driver; batch it separately.

## STOP conditions

Stop and report if:

- **`pnpm build` or the deploy preview fails.** An override incompatibility deep
  in Netlify's bundler is exactly the failure mode this plan risks. Report the
  error; do not chase it by pinning more packages.
- `pnpm install` reports peer-dependency conflicts involving the overridden
  packages.
- An override does not actually remove its advisory — that usually means the
  vulnerable version is still reachable by another path and needs the scoped
  `"parent>child"` form instead. Report before guessing at a path expression.
- The remaining high count is anything other than 3 after Step 3.
- Any verification fails twice after a reasonable fix attempt.
