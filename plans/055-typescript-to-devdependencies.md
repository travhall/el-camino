## Why this matters

`typescript` is listed in `dependencies` (`package.json:50`) rather than
`devDependencies`. TypeScript is a compile-time tool — the Netlify SSR function
bundle doesn't execute it at runtime. Shipping it in `dependencies` adds ~16 MB
to the installed bundle and signals to downstream consumers (if this were ever
published as a package) that TypeScript is a runtime requirement.

Additionally, both `typescript@6.0.3` (the project's version) and
`typescript@5.9.3` (pulled in by `@typescript-eslint` as a peer) are installed
simultaneously. `@typescript-eslint` 8.x explicitly supports TypeScript ahead
of its declared peer range, so collapsing to one version via `pnpm.overrides`
is safe and removes the duplicate ~16 MB on-disk copy.

## Steps

### Step 1: Move typescript from dependencies to devDependencies

Open `package.json`. In the `"dependencies"` object, remove:
```json
"typescript": "6.0.3"
```

In the `"devDependencies"` object, add:
```json
"typescript": "6.0.3"
```

**Verify**: `node -e "const p=require('./package.json'); console.log('dep:', !!p.dependencies?.typescript, 'dev:', !!p.devDependencies?.typescript)"` → `dep: false dev: true`

### Step 2: Add pnpm override to collapse dual TypeScript install

In `package.json`, add or extend the `"pnpm"` section:
```json
"pnpm": {
  "overrides": {
    "typescript": "6.0.3"
  }
}
```

If a `"pnpm"` section already exists (check the file), add `"overrides"` inside
it or add `"typescript": "6.0.3"` to an existing `"overrides"` block.

**Verify**: `node -e "const p=require('./package.json'); console.log(JSON.stringify(p.pnpm?.overrides))"` → shows `{"typescript":"6.0.3"}` (possibly merged with other overrides).

### Step 3: Run pnpm install

```bash
pnpm install
```

Expected: exit 0, lockfile updated.

**Verify**: `grep -c "^typescript@" pnpm-lock.yaml` → should return 1 (one version entry), down from 2.
